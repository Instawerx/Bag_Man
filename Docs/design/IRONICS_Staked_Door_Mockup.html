Handoff — Staked Play door

The buy-in door behind R98's split. Same four axes as the League door, plus the stake axis that exists nowhere else — and minus the league control, because staked play is Pro Mod only.

Chrome is identical to the League door, deliberately. §10.2 makes chrome the app's own furniture, the same for every player; identity is registry-resolved. The two doors differ by content and density — this one carries a denomination axis, a stake block and a house-rules panel — never by palette. Stake entry — §4, and why there is no slider

Presets primary, numeric secondary, no slider. §4.1 rejects the slider on four grounds: it is imprecise by construction (players land on 447 meaning 450), it is worst on the axis it appears to optimise, it is poor on touch, and it implies a continuum where the design has discrete tiers.

The band — §4.2, not optional

The failure it prevents: a player enters 450, is matched against 500, and concludes the system cheated them. Nothing went wrong — banding is the design — but the interface let them form a belief it was never going to honour. An interface that accepts an exact number without qualifying it has made a promise on the matcher's behalf.

  • The band updates live as the value changes, so the player sees the band before committing and can see the boundary they are near.
  • The band is stated in the same place as the value — never a tooltip or help text. "A qualification the player has to go looking for is a qualification that was not made."
  • Snapping is the server's (R59). The UI displays the band; it never re-implements the rule. Tie between rungs goes down — a player is never quietly pushed up a tier.
  • Band width is ±20% of the snapped rung and widens with wait time, capped, with the centre never moving (R60).

Population — per size AND per stake band

§5 requires counts "per size and per stake band". The staked door renders both: size tiles carry their own counts, and each stake preset carries the population of that band. A rung nobody is playing shows as cold — hollow dot, 62% opacity, italic — and stays selectable.

  • Switching denomination re-bases everything: ladder, currency suffix, balance reference and the band all change together. The entered amount does not carry across — 1,000 W and 1,000 V are not the same bet, and carrying the number would imply they are.
  • Amount below the lowest rung: snaps up to it, and the band display says so before commit.
  • Amount above the highest rung: clamps to the top rung; the field does not accept a value the ladder cannot express.
  • Non-integer / non-positive input: rejected at the field. The server rejects too (E1) — this is convenience, not the guard.
