Character Creator — roadmap and tracker

Build order for the player character creator, derived from the CC-READ-1 through CC-READ-4 forensic passes. Each phase carries an entry gate; no phase starts until its gate is green. Status reflects what disk proves, not what documents assert.

NUMBERING DIVERGENCE — read this before matching a tag to a row. Operator block numbering and this roadmap’s row numbering are not the same scheme, and one pair collides outright:
  • The block called “CC-4.2 · SLOT WIRING” is this roadmap’s CC-6.2 (“Slot SKUs + max-slot upgrade”). The tag cc-4-2-done follows the block number, so it closes CC-6.2 below.
  • This roadmap’s CC-4.2 is the lapse rule (“freeze, never mutate”). cc-4-2-done does not close it. Its state is unverified in this pass and its pill is deliberately left untouched — the BuildProbe carries lapse arms (L1-lapse-cap1 … L4-read-restored), so it may well be implemented, but no tag asserts it and nothing here will assert it either.
Rows below were flipped to DONE only where a row maps 1:1 onto a tag that exists. Rows with an ambiguous mapping keep their 2026-08-17 pill rather than gaining a status nobody measured.

CC-5.2 is deliberately still open. cc-5-2-done was withheld by ruling; the hue-arc work is banked but the tag was not cut. That is an accurate open, not a gap.

Proof standard. ✅ means demonstrated in PIE on a controllable pawn — two clients wherever replication is claimed. Never "compiles" or "looks right". Each phase ends with a commit, a push to personal/main, triple-hash verification, and a clean tree.
The live tracker is untrusted for this programme. BAG_MAN_LIVE_TRACKER.html was rebuilt from archived docs and reports 23 identities; disk reports 28 across every registry independently (DefaultGameplayTags.ini:40-67, DA_AFL_BrandEdgeMap, DA_AFL_ColorIdentityRegistry, robot BPs, catalog rows). ironics.org reports 18. Correcting the live tracker is its own item — CC-X1 below — and must not be folded into a creator phase.
